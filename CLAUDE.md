# FutureFlowAI_mods — Claude Code plugins, skills en mods van FutureFlowAI

Eigen Claude Code plugins. Elke submap is één plugin; `.claude-plugin/marketplace.json` in de root maakt de repo installeerbaar als marketplace (`futureflowai-mods`). Een plugin kan een mod zijn (hooks-module), een bundel skills, of beide.

## Structuur

```
FutureFlowAI_mods/
├── CLAUDE.md
├── README.md                         ← tabel met alle plugins (bij elke nieuwe plugin bijwerken)
├── .claude-plugin/marketplace.json   ← lijst van alle plugins (bij elke nieuwe plugin bijwerken)
├── futureflow-skills/                ← skills-plugin
│   ├── .claude-plugin/plugin.json
│   └── skills/<skill-naam>/SKILL.md  ← één map per skill (+ eventuele scripts/referenties)
├── content-skills/                   ← skills-plugin, overgenomen van Ootto (MIT)
├── futureflow/                       ← één mod: slots, minify, skin, voortgang, dashboard /futureflow;
│                                        bridge/ = de proxy van claude-or (start via de shim, niet via de mod)
└── voice-chat/                       ← één mod
    ├── .claude-plugin/plugin.json    ← naam, versie, beschrijving
    ├── hooks/hooks.json              ← { "modules": ["./register.tsx"] }
    ├── hooks/register.tsx            ← de hooks-module (draait in Claude Code, geen Node/DOM)
    ├── bridge/                       ← losse Node-processen die de mod start (wel Node)
    ├── tests/*.test.ts               ← `claude plugin test <mod>`
    ├── .env                          ← secrets, NIET in git
    └── .env.example                  ← wel in git
```

## Regels

- **Pluginnamen** mogen niet beginnen met `claude-`, `anthropic-` of `cc-plugin-` (gereserveerd; validatie faalt).
- **Hooks-module ≠ Node.** `hooks/register.tsx` heeft geen `fs`, `child_process`, `fetch` of `WebSocket`. Alles via `$`: `$.process.spawn`, `$.process.run`, `$.fs` (lezen/schrijven, maar niet atomair aanmaken of verwijderen), `$.http.fetch` (ook over een Unix-socket met `socketPath`), `$.env.get` (alleen string-literals), `$.plugin.root`. Wat echt Node nodig heeft (microfoon, websockets naar derden) hoort in een `bridge/`-script dat de mod spawnt.
- **Secrets** via `userConfig` in `plugin.json` met `"sensitive": true`: Claude Code vraagt ze bij installeren en bewaart ze in de keychain; de mod krijgt ze in `register(on, options)` en geeft ze bij spawnen als `env` door aan de bridge. `<mod>/.env` (chmod 600) is alleen de terugval voor ontwikkelen. Nooit committen; `.env.example` meenemen bij elke nieuwe variabele.
- **Binaries uit Homebrew** (`ffmpeg`, `ffplay`, `node`): de desktop-app heeft een kaal PATH, en `argv[0]` wordt op dát PATH gezocht, niet op de `env.PATH` die je meegeeft. Start dus via `['/usr/bin/env', 'node', …]` met `env: { PATH: '/opt/homebrew/bin:…' }` (Windows: gewoon `node`).
- **`tool.check`** krijgt de argumenten in `e.input` (`e.input.command` voor Bash), niet plat zoals `tool.call`, en ze liggen vast: een ander oordeel vraag je op met `$.tool.check({ tool, input })`.
- **`tsc -p <mod>`** kan in een sessie met veel MCP-servers falen op TS2589 (te diepe types door de union van alle MCP-tools). Type-check dan zonder `claude-code-mcp` in `types`.
- **Unix-socket-paden** onder `/tmp` houden; macOS kapt af bij ~104 tekens.
- **Gedeelde code** tussen hooks-module en Node-scripts: pure `.mjs` zonder Node-API's (bv. `agent-slots/lib/classify.mjs`), met een `.d.mts` ernaast voor de types.
- **Geen variabele `h` in een `.tsx`-module**: JSX compileert naar de globale `h`; een `h` in scope (bv. `list.map(h => …)`) breekt het tekenen met "h is not a function".
- **Mock-antwoorden in `*.test.ts`**: een test-hook op `$`-aanroepen (`env.get`, `session.id`, `process.run`) geeft `{ value }` terug, niet de waarde zelf.
- Taal van UI-teksten en code-commentaar: Nederlands; README's in het Engels.

## Checken vóór commit

```bash
claude plugin validate <mod>
claude plugin test <mod>
node --check <mod>/bridge/*.mjs              # voice-chat en futureflow (or-proxy)
node --test futureflow/tests/*.test.mjs    # pure lib en CLI's van futureflow
```

Types voor de editor legt Claude Code zelf in `<mod>/.claude-plugin/types/` zodra de mod geladen is (gitignored); `tsc -p <mod>` type-checkt dan.

## Ontwikkelen met hot reload

Tijdens een sessie laadt Claude Code mods uit `~/.claude/dev-mods/<sessie-id>/`. Werkwijze: de mod blijft hier in de repo staan en in die map komt een symlink naar `FutureFlowAI_mods/<mod>`. Wijzigingen hier worden dan na elke beurt opnieuw geladen.

Vast installeren (alle sessies):

```bash
claude plugin marketplace add /pad/naar/FutureFlowAI_mods
claude plugin install voice-chat@futureflowai-mods
claude plugin install futureflow@futureflowai-mods
claude plugin install futureflow-skills@futureflowai-mods
claude plugin install content-skills@futureflowai-mods
```

Na een wijziging: `/reload-plugins` in de sessie (een lokale marketplace wordt direct uit deze map gelezen).

## Plugins

### futureflow
Eén mod die agent-slots, minify en een skin bundelt, met voortgangsbalk en dashboard `/futureflow` (0.10: tabs 1-4: Overzicht, Wisselen, Zuinig, Instellingen). Ontwerp: `docs/superpowers/specs/2026-11-08-futureflow-supermod-design.md` (met *Uitbreiding 9-11-2026* en *Uitbreiding 10-11-2026*); plan Accounts: `docs/superpowers/plans/2026-11-10-futureflow-6-accounts.md`; plan OpenRouter: `docs/superpowers/plans/2026-11-10-futureflow-7-openrouter.md`.
- Eén hooks-module: per event mag maar één ongematchte handler bestaan. Onderdelen exporteren `startX($)` en gematchte handlers; `register.tsx` heeft de enige `session.start`, `minify.tsx` de enige `turn.complete`, `slots.tsx` de enige ongematchte `tool.call` en `session.end`.
- Skin = claude-skins 0.5.16 (MIT, commit `cf0d39f`) in `hooks/skins/`, met skin `futureflow` als standaard. Elke eigen wijziging heeft een `futureflow:`-commentaar; de lijst staat in `NOTICE`. Upstream-update = handmatig diffen tegen die commit.
- `classic.SessionStart`, `session.append` en `prompt.compose` niet gebruiken: Claude Code slaat ze bij een zelf geïnstalleerde plugin over en zet bij elke sessie een melding in beeld.
- De validator weigert `$` doorgeven aan een pijl-functie (`const f = ($) => …`); gebruik `function f($) {}`.
- `types` in `plugin.json` moet één zelfstandig bestand zijn: geen `import` in `types/index.d.ts`.
- Een fout in de `tool.call` van één onderdeel slaat de hele `tool.call` van futureflow over. Skin meet daarom alleen in try/catch en laat de aanroep nooit mislukken.
- Slots verpakt zware Bash-commando's; wie het commando toont of beoordeelt, pakt het eerst uit met `unwrapCommand` (`lib/classify.mjs`).
- `tsc` alleen draaien als `.claude-plugin/types/` bestaat: zonder die map valt `noEmit` weg en schrijft `tsc` overal `.js`-bestanden.
- Voortgang (`hooks/voortgang.tsx`, `lib/voortgang.mjs`): takenlijst uit TaskCreate/TaskUpdate, TodoWrite en `mcp__ccd_turn__update_plan`; `mcp__ccd_turn__wrap_up` vinkt alles af (de desktop-app sluit een plan af zonder laatste update_plan), daarna 5 s een ✓-regel en weg. Alleen de hoofdsessie (`e.agentId === undefined`).
- Takenlijst in de terminal: een interactieve terminalsessie heeft geen TaskCreate/TaskUpdate zonder env `CLAUDE_CODE_ENABLE_TODO_TOOLS=true` (live gemeten). Vinkje in tab Stijl (`stijl-takenlijst`) → `cli/api.mjs takenlijst aan|uit|status` zet of haalt alleen die ene regel uit `env` in `~/.claude/settings.json`; stand eenmaal gelezen in atom `stijl.takenlijst`, geldt voor nieuwe sessies.
- Connectors (tab 5): uitzetten = `projects[<sleutel>].disabledMcpServers` in `~/.claude.json`, met als sleutel de git-root van de sessiemap (`git rev-parse --show-toplevel`; een worktree is zijn eigen sleutel), anders de map zelf. Alleen via `cli/connectors.mjs` (atomisch, kapot bestand = niets schrijven). Knoppen alleen voor `claude.ai …`, `plugin:…` en servers uit `mcpServers`/`.mcp.json`; servers van de app en van mods (`ccd_*`, `Claude_*`, `terminal`, `futureflow`, …) staan op één regel "Intern (app en mods)". De lijst staat in atom `connectors.lijst` (lezen bij openen, na een klik, elke 30 s); tekenen start geen CLI.
- API (tab 6): key in de sleutelhanger, item service `futureflow-anthropic-api`, account `futureflow`; `apiKeyHelper` = `/usr/bin/security find-generic-password -s futureflow-anthropic-api -a futureflow -w` in `~/.claude/settings.json`. futureflow zet of haalt alleen precies die waarde weg; een andere helper → exit 3. De key gaat alleen via stdin (hook → `cli/api.mjs` → `security -i`). Geldt voor nieuwe terminal-sessies; in API-modus zijn de claude.ai-connectors uit. Gemeten 10-11-2026: een desktop-sessie (host-login, `CLAUDE_CODE_SDK_HAS_HOST_AUTH_REFRESH`) riep een globale `apiKeyHelper` in ~3 min en meerdere beurten niet aan, een losse `claude --settings <bestand met helper>` wel. API blijft dus globaal (geen `claude-api` nodig). Of al lopende terminal-sessies de helper live oppakken is niet gemeten.
- Accounts-ketting (`ketting` in `lib/accounts.mjs`, besluit Colin 10-11-2026): `sessieLimieten` zijn de verse meting van het actieve account; een kandidaat zonder verse meting (< 15 min) = wachten (`null`), niet naar de API, behalve als het actieve account op 100 % staat. Een wissel met de hand bij auto aan geldt tot de reset van het venster van de laatste wissel (`handmatigTotVan`, store `accounts.handmatigTot`); auto uit/aan beëindigt dat.
- Auto-wissel (`beslis` in `lib/api.mjs`): naar API vanaf `hoog`, terug pas als geen gemeten venster nog ≥ `hoog` staat en het venster van de wissel onder `laag` of gereset is; 5 min wachttijd. Een wissel met de hand gaat voor (`handmatigTot` = reset van het venster; met de hand naar API zet auto nooit terug); auto uit/aan beëindigt dat. Wisselen loopt los van de beurt (`apiMeetLos` ná `next(e)`).
- CLI-spawns krijgen een vaste `env` (`SECURITY_BIN=/usr/bin/security`, `SETTINGS_JSON=''`, `CLAUDE_JSON=''`): `$.process.run` legt `env` óver de host-env, dus anders lekken die testvariabelen uit een settings-`env`-blok in.
- Prijzen in `lib/api.mjs` (`PRIJZEN`, per model-id, met bron en datum) zijn een schatting; bij een nieuw model de tabel en `tests/api-lib.test.mjs` bijwerken. Onbekend model rekent als Sonnet 5.5.
- Accounts (tab 7, `/accounts`; naar claude-swap, MIT, commit `5ac68bfb`): wisselen tussen Colins eigen, apart betaalde abonnementen, alleen in de terminal en het standaardprofiel. Alles met sleutelhanger, `~/.claude.json`, locks en netwerk via `cli/accounts.mjs` (alleen builtins; exit 1 gebruik, 2 bestand kapot, 3 niet ingelogd/identiteit, 4 onbekend, 5 sleutelhanger, 6 niets te doen, 7 bezig, 8 eigen profiel, 9 opnieuw inloggen). Sleutelhanger: `futureflow-accounts`, `-vorige`, `-redding`, account `<accountUuid>:<orgUuid>`; kopie zonder gedeelde sleutels (`mcpOAuth`, `pluginSecrets`, …) via stdin, alleen het live item `Claude Code-credentials` (~12 KB) via argv-hex (besluit Colin). State in `~/.claude/futureflow/accounts/` (niet onder `FUTUREFLOW_HOME`: de CLI kent die niet). Geen voorwaarden-melding (besluit Colin); wel "apart betaald abonnement" en "nooit /logout, log in met /login".
- Accounts-verbruik: zuiniger dan claude-swap omdat de accounts ook op andere machines draaien: vloer 360 s per account, actief tot 600 s, kandidaat 600-900 s, uitgeput 1200 s, na een 429 ≥ 600 s ×1,5 tot 1800 s. Auto beslist alleen op metingen < 15 min (`VERS`); de tab toont de leeftijd.
- Accounts-sessiebestanden: de mod schrijft `sessies/<sessionId>.json` (`bezig` bij `turn.start` via de skin, hartslag ≤ 1× per 30 s via een gematchte `tool.call`, `tussen` bij `turn.complete` via minify, `weg` bij `session.end` via slots); alleen terminal, alleen de hoofdlus. De CLI telt daarnaast Claude Code's `~/.claude/sessions/<pid>.json` (alles behalve desktop en `idle`; onleesbaar = bezig). Het eigen sessiebestand `bezig` telt ook (nooit midden in de eigen beurt wisselen; de mod controleert `beurtBezig` bovendien vlak voor `switch`); alleen het eigen Claude Code-record (`--ikzelf` en `process.ppid`) telt niet. Bezig → exit 7 met `wie` → wachtregel boven de prompt; na 10 min melding en pas na de volgende beurt opnieuw. Exit 7 zonder `wie` (lock, login niet te controleren) = niets gewijzigd, volgende besluit opnieuw.
- Accounts-ketting (`ketting` in `lib/accounts.mjs`): met accounts-auto aan en ≥ 2 accounts in de rotatie (`kettingAan`) beslist `accountsMeetLos` (na een beurt en na `session.measure`, ≤ 1× per minuut, nooit midden in een eigen beurt, nooit in de desktop-app): eerst een ander abonnement met ruimte, alleen als alle vol zitten `wissel($,'api',…)` uit `api.tsx`, en terug (`switch` + `wissel($,'abonnement',…)`; is het doel al actief, alleen de modus). `apiMeet` doet dan niets; anders blijft het oude API-gedrag. Stand stil = wisselen met toast; stand vragen = regel boven de prompt met Wissel/Niet nu (30 min, store `accounts.nietNuTot`). Een wissel uit een andere sessie geeft 10 s een groene regel (leest `accounts.json`, geen CLI).
- Accounts-regel (eindreview 0.5.1): bij twijfel over de live login niet wisselen of verversen (exit 7, niets gewijzigd). `ververs` POST nooit als de keten (misschien) live is: onder `refresh-<account>.lock`, vlak voor de POST, identiteit en live refresh-token opnieuw lezen. `switch` houdt `refresh-<doel>.lock` vast tijdens het lezen van de doelkopie en het schrijven (volgorde wissel → refresh → cred → config), vangt SIGTERM/SIGINT/SIGHUP tot live item en `~/.claude.json` weer hetzelfde account noemen, stopt zonder schrijven na 30 s, en krijgt van de mod 120 s. Een uitgaande login die bij een bekend account hoort maar niet te controleren is → exit 7; redding alleen voor een aantoonbaar ander of onbekend account, en overschrijft alleen een oudere redding. Een bezette refresh-lock is een tijdelijke fout, geen exit 7.

### voice-chat
Praten met een Claude Code sessie via een Inworld-spraakagent. `/voice` zet hem aan of uit, verder `/voice voorlezen|stil|mute|unmute`. Een balk boven het invoerveld (`ui.render` op `AbovePrompt`, state in `$.state` `voice-chat.band`, contract in `types/index.d.ts`) toont of de agent luistert of praat, of Claude bezig is, welke taak de agent doorgaf, en de laatste zin.

**Agentmodus (standaard)** — `bridge/agent-bridge.mjs`:
- Microfoon (`ffmpeg -f avfoundation`, 24 kHz PCM16) → Inworld Realtime (`wss://api.inworld.ai/api/v1/realtime/session?key=<id>&protocol=realtime`, `Authorization: Basic <key>`, OpenAI-Realtime-protocol) → audio terug naar `ffplay`.
- De agent draait op Inworlds eigen LLM (`agent_model`, standaard `openai/gpt-4.1-mini`) en voert het gesprek zelf. Grote taken geeft hij door met de tool `geef_taak_aan_claude_code` (`providerData.auto_tool_response: false`); de bridge zet die als `{type:"task"}` op stdout, de mod stuurt hem in als `[via spraakagent] <taak>` en zet de taak in de balk tot de beurt klaar is.
- Teksten voor de agent (instructies, tooldefinitie, context, resultaatbericht) en de taakpoort staan in `bridge/agent-text.mjs`, zonder Node-API's, zodat `tests/` ze direct test; `agent-text.d.mts` geeft de types.
- Koppeling: `turn.start` met dat label (ook met de kop "The voice-chat plugin sent a message:" ervoor) koppelt de beurt aan de taak; alleen bij `turn.complete` van zo'n beurt gaat Claudes antwoord als platte tekst via `POST /result` terug, zodat getypte prompts er niet tussendoor lopen.
- Sessiegeheugen: bij `ready` stuurt de mod de laatste beurten van de sessie (`$.session.messages({ as: 'api' })`, zonder system-reminders en tool-blokken, max. ~6000 tekens) via `POST /context`; elke getypte beurt daarna via `POST /note`. De bridge zet ze als stille `system`-berichten (`[Sessie-context]`, `[Sessie-update]`) in het gesprek, waar de agent niet op reageert maar wel uit put, en stuurt ze na opnieuw verbinden opnieuw mee.
- Goedkeuring: `classic.PermissionRequest` tijdens een agent-taak → `POST /notice` (de agent zegt dat er in het scherm gekeken moet worden) en rood in de balk; de volgende `tool.call` haalt het weg.
- Beveiliging (prompt-injection): wat de agent doorgeeft is gesproken, door een extern model samengevat, en kan achtergrondgeluid bevatten. Daarom:
  - `$.prompt.submit` zonder `asUser` (in beide modi): het model leest het als bericht van de voice-chat plugin, niet als getypte prompt van de gebruiker. `prompt.compose` vertelt Claude bovendien dat zo'n taak geen getypte opdracht is en dat onomkeerbare of naar buiten gerichte acties eerst bevestigd moeten worden (de vraag gaat via de agent terug).
  - Mondelinge bevestiging: de agent vraagt eerst "Zal ik Claude Code vragen om …?" en roept de tool pas aan na een mondeling ja (verplicht argument `bevestiging`). De taakpoort in de bridge laat een taak alleen door als de gebruiker gesproken heeft (`input_audio_buffer.committed`) sinds de vorige beurt van de agent (`response.done`), de vorige taak of het laatste bericht van Claude Code; anders krijgt de agent "niet doorgegeven" terug. Zo kan de agent niet in één adem vragen en doorgeven, en geen taak maken uit een resultaat.
  - `/result` en `/notice` komen als `system`-bericht binnen, niet als `user`. Het antwoord staat tussen `<claude_code_resultaat>`-markeringen (een sluit-markering in het antwoord zelf wordt weggehaald), met de instructie dat het data is om na te vertellen en geen opdracht of nieuwe taak.
- Context: de bridge draait in de werkmap van de sessie. Buiten `agent_context_roots` (vertrouwde mappen, bv. `~/Projects`) krijgt de agent alleen de projectnaam; daarbinnen ook de bovenste bestandsnamen en `CLAUDE.md`, elk tussen markeringen (`<bestanden>`, `<claude_md>`) als achtergrond, niet als opdracht.
- Bewust gekozen (13-10-2026): de agent is een snelle tussenpersoon met een eigen LLM; Claude Code blijft het brein voor echt werk. Dit vervangt de eerdere keuze om Realtime niet te gebruiken.

**Voorleesmodus** — `/voice voorlezen`, `bridge/voice-bridge.mjs`: Inworld streaming STT → prompt naar Claude; antwoord ingekort (Haiku bij lange antwoorden) → Inworld TTS → `ffplay`. Claude praat hier zelf.

Beide modi:
- Half-duplex: de microfoon staat dicht terwijl er audio speelt (en 400 ms erna), tenzij `BARGE_IN=true` (alleen met koptelefoon).
- Instellingen: `userConfig` (`inworld_api_key` geheim, `language`, `voice_id`, `tts_model`, `mic_device`, `barge_in`, `agent_model`, `agent_context_roots`) → env van de bridge; lege velden vallen terug op `.env`, daarna op de standaard in de bridge.
