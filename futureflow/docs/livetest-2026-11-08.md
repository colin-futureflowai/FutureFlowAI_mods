# Live test futureflow naast de oude plugins (2026-11-08)

Automatisch deel van Taak 5 (stap 1, 2 en 6), niet-interactief: `claude -p --plugin-dir futureflow --permission-mode bypassPermissions` (Claude Code 2.1.319) vanuit een lege scratchmap met `package.json` (`dev` = `sleep 2`). `agent-slots@` en `minify@futureflowai-mods` stonden nog aan. Er is niets geïnstalleerd, uitgezet of gewijzigd.

## Uitkomst

| Check | Resultaat | Bewijs |
|---|---|---|
| a. `oud` | geslaagd | `cat ~/.claude/futureflow/oud` gaf `slots,minify` |
| b. `mod.log` | niet te bevestigen | Het bestand bestaat niet. Er is dus geen fout gelogd, maar `log` schrijft alleen bij fouten (`failOpen`, `[slots]`, `[minify]`), dus "geladen" blijkt alleen uit het bestaan van `oud`. Wel meldde `-p`: "futureflow: its tool.check hook was skipped. cc-plugin-sec-default runs first and sent the event on past it." |
| c. één keer ingepakt | geslaagd | `log.jsonl`: precies één `acquire` en één `release` (`kind":"dev"`, `command":"npm run dev"`, sessie `ecb8ba98-...`) voor die run |
| d. regels één keer | geslaagd | Tweede run, `oud` aanwezig: model antwoordt `MINIFY_BLOCKS=1` (de oude plugin) |
| e. race eerste sessie | mislukt | Na verwijderen van alleen `oud`: `MINIFY_BLOCKS=2`. De allereerste run (map `~/.claude/futureflow` bestond nog niet) gaf ook `MINIFY_BLOCKS=2`. |

## Bevinding (open)

Bij de eerste sessie na het ontbreken van `oud` komen de minify-regels twee keer binnen. `scripts/regels.sh` (SessionStart-hook) draait voordat de mod op `session.start` `oud` schrijft; het bestand ontbreekt dan, dus zegt futureflow de regels ook. Vanaf de tweede sessie klopt het. Niet gerepareerd (buiten scope van deze run). Mogelijke richting: regels.sh zelf op de oude plugin laten controleren, of accepteren dat het alleen de allereerste sessie geldt.

Bijzaak: de melding over `tool.check` die wordt overgeslagen door `cc-plugin-sec-default` hoort bij hoe `--plugin-dir` in `-p` laadt; check in de interactieve test of slots dan nog goed beoordeelt.
